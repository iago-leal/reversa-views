1. O defeito

O cabeçalho do painel anuncia npm run atualizar -- --aplicar para quem está atrasado, e o anuncia sem dizer de onde rodar. O painel abre no workspace de trabalho, que quase nunca é o clone do reversa-views. Quem copia a linha a executa onde o script não existe e recebe um erro do npm, não uma resposta do ritual.

2. A causa raiz (estado: confirmada)

O ritual já é independente do diretório corrente. scripts/atualizar.js ancora a raiz em path.resolve(__dirname, '..'), o clone onde o próprio arquivo mora, e não em process.cwd(). Chamado pelo caminho absoluto, de um diretório temporário neutro, ele conferiu o clone certo e saiu com o código certo:

$ node /Users/iagoleal/dev/reversa-views/scripts/atualizar.js
Clone em fe6a5ff, ramo master.
Em dia com a origem: não há commit a trazer.
código de saída: 0

O que prende o comando ao clone é a mediação do npm run, que resolve scripts pelo package.json do diretório corrente, e só ela. O defeito está na forma de invocação que a faixa anuncia, não no percurso que ela dispara. Isso reduz o raio da mudança ao ponto em que o comando é soletrado, e é o que sustenta o risco médio em vez de alto.

3. A estratégia escolhida

Endereço carimbado, escolhida por você no menu desta sessão, sem debate multiagente. A faixa passa a anunciar o ritual pelo endereço do clone que produziu a construção instalada, carimbado em tempo de construção.

A razão de ser esta: o painel compara a construção instalada com a origem, e o clone que a produziu é exatamente o endereço onde o ritual que a corrige mora. O carimbo já carrega versão, commit, origem e ramo pela mesma via; o endereço é a quinta constante da mesma natureza. Não exige instalação nenhuma em máquina alguma, ao contrário do executável global, e roda de qualquer diretório, ao contrário de manter o comando do clone.

A linha anunciada passa a ser, com a raiz vinda do carimbo:

node /Users/iagoleal/dev/reversa-views/scripts/atualizar.js --aplicar

O recuo, e por que ele existe

Você respondeu que ainda não sabe se o clone existe dentro do container e do Codespace. O plano trata o caso como não caracterizado: sem endereço carimbado, a faixa recua para o comando do clone, npm run atualizar -- --aplicar, que é o que uma construção anterior a esta correção produz. O recuo é também o que o preview e um host antigo produzem, e ele nunca inventa um caminho.

Limite declarado, e não escondido. Onde o clone não existir na máquina em que o painel roda, nenhum endereço embutido é alcançável, e a chamada morre em Cannot find module, do node. Isso fica escrito no README e no adendo como o que é: a atualização se faz onde o clone está, e o pacote resultante se instala no ambiente remoto. Caracterizado o ambiente, isso vira pergunta do ciclo forward, não deste conserto.
