O defeito

Nos desfechos atrasada e divergente, a faixa do cabeçalho oferece npm run atualizar como o comando a copiar. Esse comando, por RF-04, apenas confere e nunca traz commit algum. Quem copia a linha e a roda recebe um diagnóstico, nenhuma atualização, e o aviso reaparece na recarga seguinte. O comando que aplica é npm run atualizar -- --aplicar, e ele não aparece na tela.

Causa raiz (estado: confirmed)

A constante UPDATE_COMMAND em src/webview/domain/labels.ts nasceu na feature 007 (commit 8457e7f) com o comando do primeiro ato, e a suíte fixou esse valor como esperado. O caso atrasada diz quantos commits, e nomeia o comando que os aplica pede no nome o comando que aplica e exige na asserção o que confere. Nada cruza o rótulo com o que o script imprime como "Para aplicar", e os dois divergiram sem sinal.

// src/webview/domain/labels.ts:174
const UPDATE_COMMAND = 'npm run atualizar'          // <- o primeiro ato

// tests/webview-header.spec.tsx:110
expect(rótulo.command).toBe('npm run atualizar')    // <- a suíte fixa o valor errado

// scripts/atualizar.js:290
linhas.push('Para aplicar: npm run atualizar -- --aplicar')   // <- o script sabe o certo

Caminho causal

  1. RF-04 separou os dois atos e deu ao segundo o argumento explícito: npm run atualizar confere, npm run atualizar -- --aplicar aplica
  2. T019 escreveu a faixa com a constante do primeiro ato e a entregou igual em atrasada e em divergente (linhas 174, 223 e 232)
  3. A suíte fixou o valor errado na linha 110, e a asserção da linha 194 aceita qualquer linha que contenha a substring, o que a impede de acusar
  4. O script soletra o segundo ato por conta própria, sem verificação cruzada com o rótulo
  5. Quem copia a linha da faixa roda a conferência, e o aviso volta a cada recarga

Constante e asserção nascem no mesmo commit: não é regressão, e não cabe git bisect.

Estratégia escolhida

Correção direta: a constante passa a soletrar o segundo ato, npm run atualizar -- --aplicar, nos dois desfechos que pedem ação. A spec manda o mesmo comando em atrasada e em divergente, e depois do bug nº 4 o comando é o mesmo de fato: --aplicar significa "deixe a instalação em dia com este clone", e a recusa de RF-05 em clone com commit próprio é nomeada pelo próprio script no momento em que se aplica, com a contagem e a saída a tomar. O rótulo não precisa antecipá-la; a frase de divergente já avisa que há trabalho local.

Alternativas descartadas: frase própria em divergente sem comando (contraria a spec, que pede comando nos dois, e deixa o leitor sem saber o que rodar); e um teste que só troca a asserção da linha 110 (corrige a suíte sem impedir que rótulo e script voltem a divergir).
